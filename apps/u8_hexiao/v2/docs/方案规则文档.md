# U8委外核销自动化 v2 — 方案规则文档

版本: v2.0 | 日期: 2026-08-27 | 状态: 开发中

---

## 1. 背景与目标

v1 已实现"区域模板匹配批量勾选+核销"，但存在两个局限：
1. **无业务判断**——所有行一勾了之，需要人工判断的行无法区分；
2. **依赖固定坐标**——拖动列宽/换分辨率会导致坐标失效。

v2 目标：
- 按**采购类型分类 + 数量规则**自动判定每一行是"直接核销 / 修正后核销 / 跳过留人工";
- 用**元素识别(OCR 列头定位)**取代死坐标，列宽拖动不再失效;
- 提供**小界面(GUI)**：配置规则、查看判定计划、控制运行;
- 建立**测试基准**：规则引擎单元测试 + OCR 识别基准 + dry-run 计划预览。

## 2. 界面结构(实测截图分析)

窗口标题: **委外核销处理**，上下两个表格，点击上表行 → 下表联动过滤。

**上表 = 委外入库单**(24列，关键字列)：
`选择(复选框,第1列) | 委外订单号 | 供应商 | 入库日期 | 入库单号 | 仓库 | 采购类型 | 存货编码 | 存货名称 | … | 入库数量 | 件数 | …`

**下表 = 委外材料出库单**(21列，关键字列)：
`选择(复选框,第1列) | 委外订单号 | 供应商 | 业务类型 | 出库日期 | 出库单号 | … | 出库数量 | 件数 | 金额 | 未核销数量 | 待核销绝对数量 | 本次核销数量 | 未核销金额 | 本次核销金额`

工具栏: `选项 | 委外核销单 | 输出 | 自动 | 全选 | 全清 | 栏目 | 查询 | 刷新 | 帮助 | 退出`
底部合计行: 两表各有合计。

业务背景(调研结论): U8 委外核销 = 委外入库单 ↔ 委外材料出库单 配对，把发料成本归集到入库单。核销数量由系统按 BOM+损耗率带出到"本次核销数量"，允许手工修改做部分核销。界面"自动"按钮存在但跨订单发料/损耗尾差时不可靠，故仍需本工具的规则判断。

## 3. 核销判定规则(用户提供,规则的唯一权威来源)

### 3.1 采购类型分类

采购类型分为两大类(每类含若干具体类型)，映射关系在 config 的 `type_map` 中配置(GUI 可编辑):
- **A类 = 按件数核对**(如"封测编"，具体清单用户在 GUI 里维护)
- **B类 = 按数量核对**

未知类型 → 默认跳过留人工，日志提示补充配置。

### 3.2 A类(按件数)逐行判定

设: 上表行件数 = `件数上`，下表联动行件数 = `件数下`；
勾选下表行后系统带出: 本次核销数量 = `Q核`，未核销数量 = `Q未`。

| 条件 | 判定 | 动作 |
|---|---|---|
| 件数上 == 件数下 且 Q核 == Q未 | PASS | 直接点核销 |
| 件数上 == 件数下 且 Q核 < Q未 | MODIFY | 把 Q核 改成 Q未，点核销 |
| 件数上 < 件数下 | PASS | 直接点核销(部分核销，出库单留余量给后续) |
| 件数上 > 件数下 | SKIP | 出库不足，留人工 |
| 下表联动出多行 | SKIP | 该条不处理，留人工 |

### 3.3 B类(按数量)判定

| 条件 | 判定 | 动作 |
|---|---|---|
| 入库数量 < 未核销数量 | PASS | 直接点核销 |
| 入库数量 == 未核销数量 | PASS | 直接点核销(待用户确认，默认放行) |
| 入库数量 > 未核销数量 | SKIP | 留人工 |
| 下表联动出多行 | SKIP | 留人工 |

### 3.4 B类批量模式(v1 能力保留)

对 B 类也支持 v1 式批量: 区域模板匹配勾选可见行 → 滚动翻页 → 勾满 N 屏 → 点核销 → 循环。节奏参数(点击间隔/滚动格数/每批屏数)可在 GUI 调整。

## 4. 技术方案

### 4.1 元素识别(取代死坐标)——本工具成败关键

```
窗口定位: pygetwindow 按标题"委外核销处理"找窗口 → 表格区域 = 窗口内相对区域
    ↓
列头定位: 对上/下表表头条 OCR → 按"选择/采购类型/入库数量/件数/未核销数量/本次核销数量"
          等关键词锚定各列 x 坐标(容差合并) → 得到列坐标映射
    ↓
行定位:   复选框模板匹配(v1 已验证)得行 y 坐标; 下表行同理
    ↓
读数:     对单元格 (列x, 行y) 小区域 OCR → 解析数字(去千分位)
    ↓
判定:     规则引擎(纯函数, rules.py)输出 PASS/MODIFY/SKIP + 目标值
    ↓
执行:     点击/双击单元格 → 输入修正值 → 点核销 → 处理确认弹窗
```

OCR 引擎: **Windows 内置 OCR**(winsdk, Windows.Media.Ocr, 中文+数字, 离线免装)。若识别率不足，备选 PaddleOCR(重,后期评估)。

### 4.2 模块划分

```
v2/
├─ core/
│   ├─ rules.py      规则引擎(纯函数,无UI依赖) ← 单元测试基准
│   ├─ vision.py     窗口定位/列头OCR/行定位/单元格读数
│   ├─ executor.py   点击/修正输入/核销/确认弹窗(带急停+点击预算)
│   └─ applog.py     运行日志(落盘 development_log 兄弟文件 run_*.log)
├─ gui.py            tkinter 界面(调 core, 后台线程执行)
├─ main.py           CLI 入口(selftest/dry-run/plan/run-batch)
├─ config_v2.json    v2 配置(type_map/列锚点/节奏/阈值)
├─ tests/
│   ├─ test_rules.py          规则引擎基准(用例=3.2/3.3表格+截图实测数据)
│   ├─ fixtures/clipboard.png 用户实测截图(OCR基准)
│   └─ ocr_probe.py           OCR 可行性基准脚本
└─ docs/方案规则文档.md        本文档
```

### 4.3 安全设计(继承 v1)

- 急停: 鼠标甩屏幕左上角(FAILSAFE) / GUI 停止按钮 / Ctrl+C
- 点击预算: max_clicks_total 上限
- 判定保守: 规则覆盖不到的一律 SKIP 留人工，绝不猜
- dry-run: 任何新配置先出"判定计划表"预览，人工确认后才真跑

## 6. 测试基准策略

1. **规则基准**(M2): 3.2/3.3 的每个条件分支至少 1 正例 + 边界(相等/千分位/空值/多行联动)，加截图实测数据回放(上273/下20477/件数25 那行)。
2. **OCR 基准**(M3): fixture=用户截图；断言: 6个锚点列头命中且 x 坐标正确；抽样 10 个数字单元格识别值与人工标注一致。
3. **计划基准**(M4): dry-run 输出结构化计划(JSON+表格)，允许人工比对; 计划与实际执行分离，执行器只消费计划。
4. **回归**: 每次改 rules/vision 后跑 test_rules + ocr_probe，识别率不回退。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| OCR 数字误读(0/O、千分位逗号) | 读数正则清洗+小数位校验; MODIFY 前二次复读确认; 识别置信度低→SKIP |
| 列宽被拖动 | 列 x 坐标每次运行时重新 OCR 定位，不落盘缓存 |
| 下表联动刷新慢 | 选中上表行后轮询下表区域哈希变化，稳定后再读数 |
| 弹窗形态不一 | 确认策略 enter/click 可配; 未处理弹窗→暂停并提示 |
| 误核销 | 判定只 PASS 明确规则; MODIFY 仅限 3.2 定义的一种情形; 其余 SKIP |
